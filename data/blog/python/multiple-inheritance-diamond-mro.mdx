파이썬은 하나의 클래스가 여러 클래스를 상속하는 다중 상속을 지원합니다. 그런데 두 부모 클래스가 같은 조상을 상속하고 있다면, 어떤 경로로 메서드를 찾아야 할까요? 양쪽 부모를 모두 호출하다가 공통 조상의 메서드가 두 번 실행되지는 않을까요?

파이썬은 **C3 선형화로 메서드 탐색 순서(MRO)를 정하고, `super()`로 그 순서에 따라 호출을 이어 갈 수 있게 합니다.** 다만 다중 상속을 선언하는 것만으로 중복 실행까지 자동으로 막아 주지는 않습니다. 탐색 순서와 실제 호출을 나누어 살펴보겠습니다.

## 다이아몬드 문제란?

다음과 같은 상속 관계를 생각해 보겠습니다. 위쪽이 부모 클래스입니다.

```text
    A
   / \
  B   C
   \ /
    D
```

`B`와 `C`는 `A`를 상속하고, `D`는 `B`와 `C`를 상속합니다. 관계를 그리면 다이아몬드 모양이 됩니다.

여기에는 두 가지 질문이 있습니다.

- `B`와 `C`가 같은 이름의 메서드를 제공한다면 `D`는 어느 쪽을 사용할까요?
- `B`와 `C`가 각각 `A`의 메서드를 호출하면 `A`가 중복 실행되지 않을까요?

첫 번째는 메서드를 찾는 순서의 문제이고, 두 번째는 메서드를 연결해서 호출하는 방식의 문제입니다.

## MRO: 메서드를 어떤 순서로 찾을까?

먼저 같은 이름의 메서드가 여러 곳에 있는 경우를 보겠습니다.

```python
class A:
    def greet(self):
        print("A")


class B(A):
    def greet(self):
        print("B")


class C(A):
    def greet(self):
        print("C")


class D(B, C):
    pass


print([cls.__name__ for cls in D.__mro__])
D().greet()
```

```text
['D', 'B', 'C', 'A', 'object']
B
```

MRO는 Method Resolution Order의 약자로, 클래스 계층에서 메서드를 찾을 때 따르는 순서입니다. `D.__mro__` 또는 `D.mro()`로 확인할 수 있습니다.

이 예제에서는 `D`에 `greet()`가 없으므로 다음 순서인 `B`에서 찾습니다. `B.greet()`를 찾으면 그 메서드를 실행합니다. **MRO에 나열된 모든 클래스의 메서드가 자동으로 실행되는 것은 아닙니다.**

또한 순서는 `D → B → A → C`가 아닙니다. `C`도 `A`를 상속하므로, `C`의 구현을 확인하기 전에 공통 조상인 `A`로 올라가지 않습니다. 메서드 탐색에 C3 MRO를 사용한다는 내용은 [파이썬 데이터 모델 문서](https://docs.python.org/3/reference/datamodel.html#the-standard-type-hierarchy)에서도 확인할 수 있습니다.

## C3 선형화가 순서를 정하는 방법

파이썬 3의 기본 MRO 계산 방식은 C3 선형화입니다. 여러 갈래의 상속 관계를 다음 조건을 지키는 하나의 순서로 만듭니다.

- 자식 클래스는 자신의 부모보다 앞에 옵니다.
- 직접 부모를 선언한 순서를 유지합니다. `D(B, C)`라면 `B`가 `C`보다 앞에 옵니다.
- 부모의 MRO에서 정해진 클래스 간 선후 관계가 자식에서도 유지됩니다. 이를 단조성이라고 합니다.

같은 클래스는 결과에 한 번만 등장합니다. 다이아몬드 예제에서는 다음 목록을 합칩니다.

```text
MRO(D) = [D] + merge(
    [B, A, object],  # B의 MRO
    [C, A, object],  # C의 MRO
    [B, C]          # 직접 부모의 선언 순서
)
```

`merge`는 각 목록의 첫 원소를 왼쪽 목록부터 후보로 살펴봅니다. 후보가 어느 목록의 나머지 부분에도 없으면 선택하고, 모든 목록에서 제거합니다. 선택할 수 없다면 다음 목록의 첫 원소를 확인합니다.

처음에는 `B`를 선택할 수 있습니다. 그다음 첫 번째 목록의 후보는 `A`지만, 두 번째 목록의 `[C, A, object]`에서 `C` 뒤에 있습니다. 여기서 `A`를 선택하면 `C`보다 `A`가 앞서게 되므로 건너뜁니다.

따라서 `C`를 먼저 선택하고, 이후 `A`, `object`를 선택합니다.

```text
D → B → C → A → object
```

이 규칙은 단순한 깊이 우선 탐색이나 너비 우선 탐색과 다릅니다. 자세한 계산 과정은 [공식 C3 MRO 설명](https://docs.python.org/3/howto/mro.html#the-c3-method-resolution-order)을 참고할 수 있습니다.

## 부모를 직접 호출하면 여전히 중복 실행된다

MRO에 `A`가 한 번만 등장한다고 해서 `A`의 메서드를 두 번 호출할 수 없는 것은 아닙니다. 다음처럼 부모 클래스 이름을 직접 지정하면 중복 호출이 생깁니다.

```python
class A:
    def run(self):
        print("A")


class B(A):
    def run(self):
        print("B")
        A.run(self)


class C(A):
    def run(self):
        print("C")
        A.run(self)


class D(B, C):
    def run(self):
        print("D")
        B.run(self)
        C.run(self)


D().run()
```

```text
D
B
A
C
A
```

`D`가 `B.run()`과 `C.run()`을 각각 호출하고, 두 메서드는 다시 `A.run()`을 호출합니다. `A`가 두 번 출력되는 이유입니다. 이 자리에 파일 쓰기나 상태를 초기화하는 코드가 있다면, 같은 작업이 두 번 수행될 수 있습니다.

## super()는 MRO에서 다음 구현을 찾는다

같은 예제를 `super()`로 바꿔 보겠습니다.

```python
class A:
    def run(self):
        print("A")


class B(A):
    def run(self):
        print("B")
        super().run()


class C(A):
    def run(self):
        print("C")
        super().run()


class D(B, C):
    def run(self):
        print("D")
        super().run()


D().run()
```

```text
D
B
C
A
```

여기서 눈여겨볼 부분은 `B`입니다. `B`의 직접 부모는 `A`인데, `B.run()`의 `super().run()`은 `C.run()`으로 이어집니다.

일반적인 인스턴스 메서드 안에서 인자 없이 사용하는 `super()`는 그 메서드를 정의한 클래스와 `self`를 기준으로 동작합니다. `B.run()`에서는 `super(B, self)`에 해당합니다. `self`가 `D`의 인스턴스이므로, `D`의 MRO에서 `B` 다음부터 `run()`을 찾습니다.

| 호출 위치             | 탐색을 시작하는 위치 | 실행되는 메서드 |
| --------------------- | -------------------- | --------------- |
| `D.run()`의 `super()` | `D` 다음             | `B.run()`       |
| `B.run()`의 `super()` | `B` 다음             | `C.run()`       |
| `C.run()`의 `super()` | `C` 다음             | `A.run()`       |

`B().run()`을 실행할 때는 `B → A → object`라는 MRO를 사용하므로, 같은 `B.run()` 안의 `super()`가 `A.run()`으로 이어집니다. 실제 인스턴스의 클래스에 따라 다음 구현이 달라질 수 있는 것입니다. 이 동작은 [공식 `super()` 문서](https://docs.python.org/3/library/functions.html#super)에 설명되어 있습니다.

이 예제에서 `A.run()`은 호출을 끝내는 역할을 합니다. `object`에는 `run()`이 없으므로, `A.run()`에서도 무조건 `super().run()`을 호출하면 `AttributeError`가 발생합니다.

## super()를 쓸 때도 지켜야 할 약속

이처럼 각 클래스가 자신의 작업을 수행한 뒤 다음 구현에 넘기는 방식을 협력적 다중 상속이라고 부릅니다. 앞의 코드에서 `A.run()`이 한 번 실행되는 것은 각 단계가 `super()`로 한 번씩 호출을 이어 주기 때문입니다.

예를 들어 `B.run()`에서 `super().run()`을 빼면 출력은 `D`, `B`에서 끝납니다. 반대로 두 번 호출하면 뒤쪽 구현들도 반복 실행됩니다. MRO는 호출 횟수를 제한하는 장치가 아닙니다.

메서드의 인자도 서로 호환되어야 합니다. 앞의 예제는 모두 `run(self)`이므로 자연스럽게 이어집니다. 생성자인 `__init__()`도 같은 원리가 적용되지만, 클래스마다 필요한 인자가 다르면 전달 규칙을 맞춰야 합니다. `**kwargs`를 사용한다면 각 클래스가 자신의 인자를 소비하고 나머지를 전달하는 식으로 설계할 수 있습니다. 마지막 `object.__init__()`에는 처리되지 않은 인자를 넘기지 않아야 합니다.

## 일관된 순서를 만들 수 없다면?

모든 상속 관계에 대해 MRO를 만들 수 있는 것은 아닙니다.

```python
class X:
    pass


class Y:
    pass


class Left(X, Y):
    pass


class Right(Y, X):
    pass


try:
    class Child(Left, Right):
        pass
except TypeError:
    print("MRO를 만들 수 없습니다.")
```

```text
MRO를 만들 수 없습니다.
```

`Left`는 `X`가 `Y`보다 앞서야 하고, `Right`는 `Y`가 `X`보다 앞서야 합니다. 두 조건을 동시에 만족할 수 없으므로 파이썬은 **클래스를 정의하는 시점에 `TypeError`를 발생시킵니다.** 충돌하는 순서 중 하나를 임의로 선택하지 않습니다. [공식 MRO 문서의 충돌 사례](https://docs.python.org/3/howto/mro.html#the-beginning)에서도 같은 원리를 확인할 수 있습니다.

## 마치며

다이아몬드 상속을 이해할 때는 메서드를 찾는 순서와 실제 호출을 구분하는 것이 중요합니다. C3 MRO가 탐색 순서를 정하고, `super()`는 그 순서에서 다음 구현으로 연결합니다.

코드의 동작이 예상과 다르다면 먼저 해당 클래스의 `__mro__`를 확인해 보면 좋습니다. 그다음 각 메서드가 어디에서 다음 호출을 이어 가고, 어디에서 끝내는지 따라가면 공통 조상이 중복 실행되거나 일부 구현이 생략되는 이유를 찾을 수 있습니다.
